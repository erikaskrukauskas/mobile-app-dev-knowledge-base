# A human-check has more than one sense

A check that is only a picture leaves out anyone who cannot see that picture.

## Rule

If the screen uses a human-check, identify it in text and offer another mode for a different sense. Do not make the picture the only way through.

## Specify

- The modes.
- The text that explains the check.

## Check

Complete the check without using the original sense. The path finishes. Run it on a mobile client. See [Verify on a mobile client, then record](04-verify-and-record.md).

## Source

Checked 2026-10-19. [Understanding Success Criterion 1.1.1: Non-text Content](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html). The page supports this rule: If non-text content is a CAPTCHA, text alternatives identify it, and alternative forms are provided for different types of sensory perception.

Confirm that page before you rely on a platform feature. This practice does not pick a framework, a language, or a platform. A general application rule that any client could use stays in the [application-development knowledge base](https://github.com/erikaskrukauskas/app-dev-knowledge-base).
